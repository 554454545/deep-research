# 参考报告形态记录（Atypica 输出样例）

> 来源：`test.pdf`（本目录，10 页）。输入问题："为什么当代学生不再走进图书馆了"，Atypica 的最终输出。
> 用途：后期报告增强（v0.4.x）的形态参考——当前 generate_report 只产 markdown，目标形态见下。
> 记录时间：2026-08-08（文本经 pymupdf 提取，视觉经渲染 + glm-4v-flash 描述）。

## 一、报告结构（逐页）

1. **封面**：英文品牌行（INSIGHT RESEARCH REPORT）→ 大标题（当代大学生为何不再走进图书馆）→ 副标题（研究方法概述）→ 三个统计徽章（8 研究画像 / 17 社媒样本 / 5 深度访谈）→ 品牌页脚（ATYPICA.AI BUSINESS RESEARCH INTELLIGENCE · PANEL ID）
2. **研究背景**：背景叙事（悖论/危险归因）→ 引用块（来自焦点小组的背景观察）→ 核心研究问题（3 个"什么"）→ 信息来源说明（方法 × 数量 × 平台表格：社媒挖掘 17 条/焦点小组 2 轮/深度访谈 5 位）
3. **核心发现概览**：4 个发现卡片，编号 01-04，每条一个加粗标题 + 一段解释（全报告的骨架）
4. **发现详解 + 学生画像**：七种面孔（每张画像卡：名字 + 类型标签 + 到馆频率 + 2-3 句描述 + 核心需求列表）
5. **学习场景选择逻辑地图**：两条决策路径对比（路径 A 控制感优先 vs 路径 B 确定性优先，各列典型用户 + 核心决策逻辑）
6. **深度洞察·阻碍因素**："三堵看不见的墙" + 反直觉洞察（图书馆的"免费"并非绝对优势）
7. **需求分层洞察（KANO）**：三层结构——
   - 基础需求层 MUST-HAVE（影响力：流失防御；缺失即驱走用户）
   - 期望需求层 PERFORMANCE（影响力：满意度提升）
   - 惊喜需求层 DELIGHTER（影响力：新用户转化；附警告：基础层未满足时实施会产生"精装修破旧管道"的反效果）
   每层列出具体需求项 + 用户原声佐证
8. **策略建议**：优先级 P1-P5（P1 立即 / P4 12-18 个月 / P5 视情况）+ 每项具体动作 + 优先级逻辑说明
9. **实施路线图**：三阶段（止血 0-3 月 → 增效 3-12 月 → 突破）+ 每阶段快赢/具体动作/成功指标 + 风险应对
10. **附录·学生原声汇编**：按主题归类（基础设施失灵/空间与学习仪式/替代场所吸引力/改造边界）的原始引用，每条带发言人名字+标签，可溯源

## 二、视觉风格（视觉模型描述）

- **封面**：空旷书架摄影图（暖黄灯光）+ 白色背景 + 黑色居中大字标题 + 底部三个圆形统计图标（8/17/5），简约现代、学术氛围
- **内容页**：卡片式排版——核心发现用深色（黑/深灰）卡片 + 黄色圆点编号标签（01-04），白字浅灰字，浅色边框分隔；标题加粗居中的信息层级
- 整体：信息密度高但层级清晰，数字/徽章/卡片是主要视觉语言

## 三、对我们的启示（v0.4.x 报告增强）

1. **generate_report 需要扩展输入 schema**：当前只接收 `title` + `highlights`（字符串数组），目标形态需要接收结构化板块：统计徽章、核心问题列表、画像卡数组、需求分层（must/perf/delight 各带需求项）、优先级建议（P1-P5 带动作）、路线图阶段、原声引用——模型一次生成或分板块多次落盘
2. **产出形态不局限 md**：md 保留（可追溯/可 diff），增强版渲染成 HTML/PDF（参考 Atypica 的版式：封面 + 卡片 + 徽章）。后期可用 md → HTML → PDF 管线（如 pandoc/markdown-pdf，或自写 HTML 模板）
3. **内容规范**（从样例提炼的"好报告"标准）：
   - 研究背景要有"核心研究问题"（3 个左右），不是只有背景叙述
   - 发现要"概览先行"（4 个卡片）再展开
   - 画像要有"到馆频率/类型标签/核心需求"结构化字段
   - 需求分层按 KANO 三层，且每层标注"影响力定位"
   - 建议要带优先级编号 + 时间表（P1 立即…P5 视情况）
   - 附录保留用户原声（可溯源），这是"洞察可信度"的关键
